# M24-G Controlled S2 Replication Design

M24-G is needed because M24-F fixed the extraction method but did not produce a stable adoption decision. The corrected M24-F profile analysis remains `corrected_analysis_inconclusive`, so the corrected candidate profile is evidence to review, not a profile to adopt.

Corrected extraction alone is insufficient because extraction correctness does not prove response reproducibility. The same S2 direct-response question still has conflicting context from M19C, M23-C direct baseline, and the corrected M24-F refresh. A controlled replication is needed to separate extraction issues from protocol, reset, path, warm-up, battery, and environment effects.

Profile adoption remains blocked until a controlled S2 direct-response session shows that the response is reproducible under standardized conditions. Running compensation validation before that would mix compensation effects with unresolved baseline-response uncertainty.

M24-G designs the controlled replication only. It does not run hardware, create new physical data, overwrite `k1_gold_profile_v1`, adopt the M24-F corrected candidate profile, claim compensation improvement, claim deployment readiness, or start GO1/G1 work.

What can be claimed:

- A controlled S2 replication protocol is defined.
- A direct-only controlled trial plan is generated.
- Required metadata and analysis decision categories are documented.

What cannot be claimed:

- No new S2 response measurement exists from M24-G.
- No profile has been adopted.
- No compensator has been validated.
- No deployment or GO1/G1 readiness exists.
